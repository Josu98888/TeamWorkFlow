Before styling anything, check:

| Check | Where | Expect |

## Critical Rules

- `app/globals.css` is the single source of truth for colors. Raw color values exist ONLY there, once per token.
- ONLY semantic token colors in components (`bg-primary`, `text-muted-foreground`, `border-border`). NEVER raw palette colors (`bg-slate-800`, `text-white`, `bg-blue-500`).
- NEVER hex/rgb/oklch values outside `globals.css` — not in className, `style`, or JS constants.
- NEVER CSS variables in className — neither `bg-[var(--x)]` nor the v4 shorthand `bg-(--x)`.
- NEVER `dark:` color variants. Tokens already switch between light and dark.
- NEVER create a token that duplicates or nearly duplicates an existing one. Shared values use `var(--token)`.
- NEVER repeat the same class combination for the same visual concept — extract a component or `cva` variant.
- NEVER `@apply`, and NEVER copy a primitive's classes onto another element.
- Component appearance comes from `variant` / `size` props backed by `cva`, NEVER from call-site visual classes on shared controls.
- `cn()` only for conditional or mergeable classes; plain `className` for static ones.
- Write Tailwind 4 syntax (see "v3 → v4 Changes").

## Single Source of Truth (REQUIRED)

### Colors

- Raw color values exist ONLY in `app/globals.css`, once per token. Components, constants and styles only reference tokens.
- Before proposing a new token, compare its value with the existing ones. If it matches or is visually equivalent, REUSE that token — never create near-duplicates (`--brand-blue` next to an identical `--primary`).
- If a token must share another token's value, reference it instead of repeating the value:

```css
:root {
  --primary: oklch(0.205 0 0);
  --sidebar-primary: var(--primary);    /* ✅ reference */
  /* --sidebar-primary: oklch(0.205 0 0);   ❌ repeated value */
}
```

- `CHART_COLORS` and any JS color constant reference CSS variables (`var(--chart-1)`), never copied values.

### Repeated class combinations

If the same class combination for the same visual concept appears in 2+ places, extract it:

- Same element, different looks → `cva` variant in a component.
- Same element, same look → a component (`shared/components/` if agnostic, domain `components/` if business).

Rules:

- NEVER use `@apply` to bundle classes into custom CSS classes. Extract a component instead.
- `@utility` in `globals.css` only for single-purpose utilities Tailwind lacks, not for bundling existing classes.
- NEVER copy a shadcn primitive's classes onto another element. Reuse its variants:

```tsx
import Link from "next/link";
import { buttonVariants } from "@/shared/components/shadcn/button";

// ✅ Link styled as a button, reusing the button's variants
<Link href="/projects" className={buttonVariants({ variant: "outline" })}>
  Projects
</Link>

// ❌ Copy-pasted button classes
<Link href="/projects" className="inline-flex h-9 items-center rounded-md border px-4 …">
  Projects
</Link>
```

- Layout combos that are just structure (`flex items-center gap-2`) do not need extraction. Extract when the combination represents a visual concept (a card, a pill, a section header).

## Tailwind 4 CSS-First Setup (reference)

`shadcn init` generates this structure. Do NOT write it by hand unless the user asks. Use it to understand where tokens come from.

```css
/* frontend/app/globals.css */
@import "tailwindcss";

@custom-variant dark (&:is(.dark *));

:root {
  --radius: 0.625rem;
  --background: oklch(1 0 0);
  --foreground: oklch(0.145 0 0);
  --primary: oklch(0.205 0 0);
  --primary-foreground: oklch(0.985 0 0);
  --muted: oklch(0.97 0 0);
  --muted-foreground: oklch(0.556 0 0);
  --border: oklch(0.922 0 0);
  /* …card, popover, secondary, accent, destructive, input, ring, chart-1..5 */
}

.dark {
  --background: oklch(0.145 0 0);
  --foreground: oklch(0.985 0 0);
  /* …same tokens, dark values */
}

@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-muted: var(--muted);
  --color-muted-foreground: var(--muted-foreground);
  --color-border: var(--border);
  /* … */
}
```

How it works: `:root` / `.dark` hold the values, and `@theme inline` turns each `--color-<name>` into utilities (`bg-<name>`, `text-<name>`, `border-<name>`…).

When editing `globals.css`, preserve the existing structure and only add what is needed. Never delete or rename existing tokens.

### Adding a new token (design-system change — ask first)

Only after the user approves, and only if no existing token is equivalent (see "Single Source of Truth"). Define it in both themes and map it:

```css
:root {
  --success: oklch(0.62 0.17 145);            /* value approved by the user */
  --success-foreground: oklch(0.98 0 0);
}

.dark {
  --success: oklch(0.7 0.17 145);
  --success-foreground: oklch(0.15 0 0);
}

@theme inline {
  --color-success: var(--success);
  --color-success-foreground: var(--success-foreground);
}
```

```tsx
// Then, and only then:
<p className="text-success">Project accepted</p>
```

## Semantic Tokens (shadcn defaults)

Verify each token exists in `app/globals.css` before using it.

| Purpose | Classes |
|---------|---------|
| Page | `bg-background`, `text-foreground` |
| Surfaces | `bg-card text-card-foreground`, `bg-popover text-popover-foreground` |
| Secondary text / subtle areas | `text-muted-foreground`, `bg-muted` |
| Main action | `bg-primary text-primary-foreground` |
| Secondary action | `bg-secondary text-secondary-foreground` |
| Hover / highlight | `bg-accent text-accent-foreground` |
| Danger | `bg-destructive`, `text-destructive`, `border-destructive` |
| Borders & inputs | `border-border`, `border-input` |
| Focus | `ring-ring`, `outline-ring` |
| Charts | `--chart-1` … `--chart-5` (via CHART_COLORS) |

```tsx
// ✅ Semantic tokens
<h1 className="text-2xl font-bold text-foreground" />
<p className="text-sm text-muted-foreground" />
<div className="rounded-lg border bg-card p-4" />

// ❌ NEVER: raw palette, hex, dark: color variants
<p className="text-slate-400" />
<div className="bg-[#1e293b]" />
<div className="bg-white dark:bg-slate-900" />
```

Opacity modifiers on tokens (`bg-primary/10`, `bg-muted/50`) are allowed on layout or decorative elements you own, NOT on shared controls (Button, Select…).

## Styling Decision Tree

```text
Static classes?                       → className="…"            (no cn())
Conditional or mergeable classes?     → cn(…)
Component with visual variants?       → cva in the component + variant props
Same visual combo in 2+ places?       → extract component / cva variant
Truly dynamic value (computed)?       → style={{ … }}
Library prop that doesn't take class? → CHART_COLORS constant with var() (teamworkflow-frontend)
Color not covered by a token?         → check for an equivalent token → else STOP and ask
```

## `cn()`

```ts
// frontend/shared/lib/utils.ts — generated by shadcn init, do not rewrite
import { clsx, type ClassValue } from "clsx";
import { twMerge } from "tailwind-merge";

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}
```

```tsx
import { cn } from "@/shared/lib/utils";

// ✅ Conditional classes (layout/state, tokens only)
<li className={cn("rounded-md px-3 py-2", isSelected && "bg-accent text-accent-foreground")} />

// ✅ Merging an incoming className in a reusable component
<div className={cn("flex items-center gap-2", className)} />

// ❌ Static classes wrapped in cn()
<div className={cn("flex items-center gap-2")} />

// ❌ Variant styling at the call site — use cva in the component instead
<div className={cn("rounded-lg", variant === "primary" && "bg-blue-500 text-white")} />
```

## Variants with `cva`

Visual variants live inside the component. Call sites only choose a variant.

```tsx
// frontend/shared/components/StatCard.tsx
import { cva, type VariantProps } from "class-variance-authority";
import type { ComponentProps } from "react";
import { cn } from "@/shared/lib/utils";

const statCardVariants = cva("rounded-xl border", {
  variants: {
    tone: {
      default: "bg-card text-card-foreground",
      muted: "bg-muted text-muted-foreground",
      destructive: "border-destructive/50 text-destructive",
    },
    size: {
      sm: "p-3 text-sm",
      md: "p-4 text-base",
    },
  },
  defaultVariants: { tone: "default", size: "md" },
});

type StatCardProps = ComponentProps<"div"> & VariantProps<typeof statCardVariants>;

export function StatCard({ className, tone, size, ...props }: StatCardProps) {
  return <div className={cn(statCardVariants({ tone, size }), className)} {...props} />;
}
```

```tsx
// ✅ Call site: variant + layout-only classes
<StatCard tone="muted" className="col-span-2" />

// ❌ Call site: visual overrides
<StatCard className="bg-slate-800 text-white" />
```

### Mapping business values to variants

```tsx
// frontend/domains/projects/components/ProjectStatusBadge.tsx
// Requires shadcn badge (install via CLI if missing — ask first)
import type { ComponentProps } from "react";
import { Badge } from "@/shared/components/shadcn/badge";
import type { ProjectStatus } from "../types";
import { projectStatusLabel } from "../labels";

type BadgeVariant = ComponentProps<typeof Badge>["variant"];

const STATUS_VARIANT = {
  pending: "secondary",
  accepted: "default",
  rejected: "destructive",
} as const satisfies Record<ProjectStatus, BadgeVariant>;

export function ProjectStatusBadge({ status }: { status: ProjectStatus }) {
  return <Badge variant={STATUS_VARIANT[status]}>{projectStatusLabel(status)}</Badge>;
}
```

> Status → variant mapping lives in ONE component. Everywhere else renders `<ProjectStatusBadge status={…} />`; never repeat the mapping.

## Dynamic Values

Use the `style` prop only for values computed at runtime.

```tsx
import type { CSSProperties } from "react";

// ✅ Computed values
<div className="h-2 rounded-full bg-primary" style={{ width: `${percentage}%` }} />

// ✅ Custom property consumed by CSS in globals.css (rare)
<div style={{ "--progress": `${value}%` } as CSSProperties} />

// ❌ Static values in style — use classes
<div style={{ display: "flex", gap: 8 }} />

// ❌ Colors in style — use tokens
<div style={{ color: "#fff" }} />
```

## Tailwind v3 → v4 Changes (REQUIRED)

Models often write v3 syntax. Always use the v4 column.

| v3 (❌) | v4 (✅) |
|---------|---------|
| `shadow-sm` | `shadow-xs` |
| `shadow` | `shadow-sm` |
| `drop-shadow-sm` / `drop-shadow` | `drop-shadow-xs` / `drop-shadow-sm` |
| `blur-sm` / `blur` | `blur-xs` / `blur-sm` |
| `backdrop-blur-sm` / `backdrop-blur` | `backdrop-blur-xs` / `backdrop-blur-sm` |
| `rounded-sm` / `rounded` | `rounded-xs` / `rounded-sm` |
| `outline-none` | `outline-hidden` |
| `ring` (3px) | `ring-3` (`ring` is now 1px) |
| `bg-opacity-50` | `bg-black/50` (opacity modifier) |
| `text-opacity-*`, `border-opacity-*` | `text-foreground/70`, `border-border/50` |
| `flex-shrink-0` / `flex-grow` | `shrink-0` / `grow` |
| `overflow-ellipsis` | `text-ellipsis` |
| `bg-gradient-to-r` | `bg-linear-to-r` |
| `!font-bold` (important prefix) | `font-bold!` (important suffix) |
| `tailwind.config.js` theme | `@theme` in `globals.css` |

Other v4 behaviors:

- `border` without a color uses `currentColor`. Always pair it with a token: `border border-border`.
- Variants stack left to right: `*:first:pt-0` (not `first:*:pt-0`).
- Spacing utilities accept any step of the scale: `w-81`, `mt-13`, `gap-7` (no arbitrary value needed).
- Container queries are built in: `@container` on the parent, `@md:grid-cols-2` on children.

## Layout & Responsive

- Mobile-first: base classes for mobile, then `sm:` / `md:` / `lg:`.
- Prefer `gap-*` over `space-x-*` / `space-y-*` in flex and grid layouts.
- Use `size-*` for equal width and height (`size-4` instead of `w-4 h-4`).
- Use container queries (`@container` / `@md:`) for components whose layout depends on their own width.

```tsx
<div className="grid grid-cols-1 gap-4 md:grid-cols-2 lg:grid-cols-4" />

<div className="@container">
  <div className="flex flex-col gap-2 @md:flex-row @md:items-center" />
</div>
```

## Focus & Accessibility

- Use `focus-visible:` for focus styles, not `focus:`.
- NEVER remove the outline (`outline-hidden`) without a visible replacement (`focus-visible:ring-2 focus-visible:ring-ring`).
- shadcn primitives already handle focus styles — do not override them at the call site.
- Hide visually but keep for screen readers: `sr-only`.

```tsx
// ✅ Own interactive element
<a className="rounded-md outline-hidden focus-visible:ring-2 focus-visible:ring-ring" href="/projects">
  Projects
</a>

// ❌ Focus removed with no replacement
<button className="focus:outline-none" />
```

## Arbitrary Values (escape hatch)

```tsx
// ✅ One-off layout values not covered by the scale
<div className="grid-cols-[1fr_2fr_1fr]" />
<div className="max-w-[68ch]" />

// ⚠️ Prefer the scale first: w-81 instead of w-[324px]

// ❌ NEVER for colors or CSS variables
<div className="bg-[#1e293b]" />
<div className="bg-[var(--primary)]" />
<div className="bg-(--primary)" />
```

If the same arbitrary value appears 2+ times, propose a token, `@utility` or component to the user instead of repeating it.
